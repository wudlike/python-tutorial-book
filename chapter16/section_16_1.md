## 16.1 需求分析与设计

在动手写代码之前，先想清楚"这个系统要做什么"。需求分析是软件开发的起点——把模糊的想法变成清晰的功能列表。

### 16.1.1 功能需求

通过与"用户的对话"，我们梳理出以下核心需求：

| 编号 | 功能 | 描述 |
|------|------|------|
| F1 | 添加记录 | 记录一笔收入或支出，包含金额、类别、日期、备注 |
| F2 | 查看记录 | 按列表展示所有账单，支持按类别和时间筛选 |
| F3 | 编辑记录 | 修改已有记录的内容 |
| F4 | 删除记录 | 删除一条或多条记录 |
| F5 | 统计分析 | 按类别统计收支总额，按月份展示趋势 |
| F6 | 数据持久化 | 所有数据保存到本地数据库，重启不丢失 |
| F7 | 导出报表 | 将账单数据导出为 CSV 文件 |

### 16.1.2 系统架构设计

整个系统分为三层，各司其职：

```
┌─────────────────────────────┐
│        表现层 (UI)           │  ← Tkinter 图形界面
│   窗口、按钮、列表、图表      │
├─────────────────────────────┤
│        业务逻辑层             │  ← 数据处理、统计计算
│   增删改查、分类统计          │
├─────────────────────────────┤
│        数据层                │  ← SQLite 数据库
│   存储账单记录               │
└─────────────────────────────┘
```

这种"分层架构"的好处是：如果需要把 Tkinter 界面换成 Web 界面，只需改动表现层，业务逻辑层和数据层完全不用动。

### 16.1.3 模块划分

确定系统由以下 Python 模块组成：

| 模块文件 | 职责 |
|----------|------|
| `models.py` | 数据库连接、建表、CRUD 操作 |
| `finance_ui.py` | Tkinter 界面构建和事件绑定 |
| `main.py` | 程序入口，启动窗口 |

完整项目代码放在 `projects/personal_finance/` 目录下。你可以进入该目录直接运行 `python main.py` 启动程序。
