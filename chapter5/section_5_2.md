## 5.2 元组——不可变的"时间胶囊"

如果说列表是一个可以随时打开整理的行李箱，元组就是一个用火漆封印的信封——里面的内容一经封存，就无法再更改。这种"不可变性"看似是一种限制，实则是 Python 在你和可能出现的 Bug 之间筑起的一道保护墙。

### 5.2.1 什么是元组？

元组和列表长得非常像，唯一的创建区别是使用**圆括号** `()` 而非方括号：

```python
point = (3, 5)                # 一个坐标点
rgb = (255, 128, 0)           # 一个 RGB 颜色值
person = ("张三", 20, "男")    # 一条人员记录
empty = ()                    # 空元组（几乎用不到）
```

但真正的区别不是括号——是**不可变性**。一旦元组创建，你就不能往里面加元素、删元素、或修改已有元素的值。任何试图修改元组的操作都会抛出错误：

```python
colors = ("红", "绿", "蓝")
# colors[0] = "黄"         # TypeError！元组不支持修改
# colors.append("白")      # 报错！元组没有 append 方法
```

---

\begin{definitionbox}
**元组 vs 列表：什么时候用哪个？**

| 场景 | 推荐 | 理由 |
|:-----|:----:|:-----|
| 存储坐标点 `(x, y)` | 元组 | 坐标是一组不可分割的整体，不应该被修改 |
| 存储购物车商品 | 列表 | 用户随时会增删商品 |
| 函数返回多个值 | 元组 | `return x, y` 本质上返回的就是元组 |
| 处理一批待办事项 | 列表 | 需要按序处理、标记完成、增删任务 |
| 作为字典的键 | 元组 | 字典的键必须是不可变类型，列表不能当键 |

简单的判断法则：如果你的数据在整个程序运行期间不应该被修改，就用元组来锁定它。这样做还有一个额外好处——当别人读你的代码时，看到元组就知道这些数据是"只读"的，无需担心它在某处被意外篡改。
\end{definitionbox}

---

### 5.2.2 元组的基本操作

元组虽然不能修改，但读取和遍历操作与列表完全一致：

```python
colors = ("红", "绿", "蓝")

print(colors[0])       # 红（索引）
print(colors[-1])      # 蓝（负索引）
print(colors[1:3])     # ('绿', '蓝')（切片——返回新元组）

for c in colors:       # 遍历
    print(c)

print(len(colors))     # 3（元素个数）
print("绿" in colors)  # True（成员判断）
```

---

\begin{tipbox}
**关于那个奇怪的逗号——单元素元组**

创建只有一个元素的元组时，必须在元素后加一个逗号：

```python
t1 = (42)          # 这不是元组！括号被当成数学括号，t1 就是整数 42
t2 = (42,)         # 这才是只有一个元素的元组
print(type(t1))    # <class 'int'>
print(type(t2))    # <class 'tuple'>
```

不加逗号的话，Python 会把 `(42)` 理解为 `42`，圆括号仅仅是数学中的优先级括号。这个细节坑过无数初学者，记住一条口诀：**单元素元组 = 元素 + 逗号**。
\end{tipbox}

### 5.2.3 元组解包——一次性提取多个值

元组最优雅的用法之一叫"解包"：把元组中的多个值一次性赋给多个变量。

```python
point = (10, 20)
x, y = point                # 解包：x=10, y=20
print(f"x={x}, y={y}")

rgb = (255, 128, 0)
r, g, b = rgb               # 解包：r=255, g=128, b=0

a, b = 1, 2                 # Python 中交换变量的一行写法，本质也是元组解包
print(a, b)                 # 1 2
```

解包也支持用 `*` 来收集多余的元素：

```python
first, *middle, last = (1, 2, 3, 4, 5)
print(first)                # 1
print(middle)               # [2, 3, 4]（注意：* 收集的结果是一个列表）
print(last)                 # 5
```

解包最常见的应用场景是函数返回多个值——其实 `return a, b` 返回的就是一个元组，接收方用解包语法拆开：

```python
def get_user():
    return "小明", 25, "北京"     # 返回元组

name, age, city = get_user()      # 解包接收
```

### 5.2.4 元组的"不可变"只到第一层

这里有一个需要特别注意的微妙之处：如果元组中包含可变对象（如列表），元组本身不可变，但里面的列表仍然可以修改。

```python
t = (1, [2, 3], "hello")
t[1].append(4)             # 允许！因为修改的是 t[1] 这个列表，不是元组本身
print(t)                   # (1, [2, 3, 4], "hello")

# t[1] = [5, 6]            # 报错！试图修改元组中位置 1 的引用本身
```

理解这个行为的关键在于：元组的"不可变"指的是它存储的**引用关系**不可变（不能把位置 1 指向别的对象），而不是它引用的**对象内部**不可变。这就好比你把一个快递盒封死了，不能再换盒子里的物品编号——但如果某个物品本身是个抽屉，你还是可以打开抽屉往里面放东西。通常情况下应该避免在元组中放入可变对象，否则"不可变"的保护意义就被削弱了。
