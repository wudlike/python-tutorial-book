## 3.1 注释和代码规范

写代码不仅是让计算机看懂，更要让人能看懂。注释和代码规范就是实现这一目标的核心工具——好的注释能解释代码"为什么这么写"，规范的格式能让代码结构清晰，方便自己日后维护，也便于他人协作。

### 3.1.1 注释：给代码"加说明"

注释是代码中不会被计算机执行的文字，专门写给人看的。Python 中有两种常用注释方式，分别适用于不同场景。

#### 1. 单行注释

语法：在需要注释的内容前加 `#`，`#` 后面的文字会被 Python 忽略。

示例：

```python
# 这是一行单行注释，不会被执行
print("Hello World")  # 这也是单行注释，可写在代码后面

# 以下代码用于计算 1+2 的结果
result = 1 + 2
print(result)  # 输出计算结果
```

**适用场景：**
- 解释单行代码的作用（如 `# 输出计算结果`）
- 临时注释掉某行代码（调试时常用，想暂时不执行某行，加 `#` 即可）
- 标注代码的关键步骤（如 `# 读取用户输入`）

#### 2. 多行注释

语法：用连续三个双引号 `"""` 或三个单引号 `'''` 包裹多行文字，中间的内容会被视为注释。

示例：

```python
"""
这是多行注释的第一行
这是多行注释的第二行
适合用来写一段完整的说明，比如函数的功能、参数含义等
"""
print("我是可执行代码")

'''
单引号的多行注释效果和双引号一样
选择一种风格保持一致即可
'''
name = "Python"
```

**适用场景：**
- 为一个函数、类或模块写详细说明（说明功能、参数、返回值等）
- 对一段复杂逻辑做整体解释（比如算法的实现思路）
- 作为代码文件的开头说明（如作者、创建日期、功能概述）

#### 3. 写注释的 3 个原则（新手必看）

\begin{tipbox}

**注释三原则**

1. **不写废话**：不要注释"显而易见"的代码

   ```python
   x = 10  # 把10赋值给变量x    # ← 多余！删掉
   ```

2. **解释"为什么"，而非"是什么"**：代码本身能告诉人"做了什么"，注释要说明"为什么这么做"

   ```python
   # 因为用户ID不能为负数，所以取绝对值
   user_id = abs(input_id)
   ```

3. **保持更新**：修改代码时，一定要同步修改相关注释，避免"代码改了，注释没改"导致误解

\end{tipbox}

### 3.1.2 代码规范：让代码"有规矩"

代码规范是写代码的"格式约定"，就像写文章要分段、用标点一样。遵循规范的代码看起来更整齐，团队协作时也能减少沟通成本。Python 有一套官方推荐的规范——**PEP 8**，以下是新手必须掌握的核心规则。

#### 1. 缩进：4 个空格（Python 的"语法命脉"）

Python 用缩进来区分代码块（比如 `if` 语句、循环、函数体），这是**强制要求**，缩进错误会直接导致程序报错。

正确示例：

```python
if score >= 60:
    print("及格")       # 缩进4个空格，表示这行属于if的代码块
else:
    print("不及格")     # 同样缩进4个空格
```

错误示例（缩进不一致）：

```python
if score >= 60:
  print("及格")        # 用了2个空格，和其他代码块不一致
    print("继续努力")  # 缩进混乱，会报错
```

> **提示：** 推荐在编辑器中设置"按 Tab 键自动转换为 4 个空格"（VS Code、PyCharm 等都支持）。

#### 2. 空格：让代码更整洁

适当的空格能让代码更易读，核心规则：

- **赋值符号 `=` 前后加空格：**

  ```python
  name = "Alice"  # 正确：= 前后有空格
  age = 18        # 不推荐：缺少空格，看起来拥挤
  ```

- **运算符（`+` `-` `*` `/` 等）前后加空格：**

  ```python
  total = a + b * 2   # 正确
  total = a+b*2       # 不推荐
  ```

- **逗号 `,` 后加空格：**

  ```python
  fruits = ["apple", "banana", "orange"]  # 正确
  fruits = ["apple","banana","orange"]    # 不推荐
  ```

#### 3. 行长度：88 字符

一行代码太长会导致阅读时需要左右滚动，影响体验。PEP 8 推荐一行不超过 **88 个字符**（大多数编辑器会显示"竖线提示"）。

换行技巧——在逗号后或运算符前换行，保持缩进对齐：

```python
# 过长的代码（不推荐）
result = (a + b * c - d / e) * 100 + (f - g) * 200 - h * 50

# 换行后（推荐）
result = (a + b * c - d / e) * 100 + \
         (f - g) * 200 - h * 50  # 用 \ 连接换行，第二行缩进对齐

# 列表/字典换行（更自然）
students = [
    "张三", "李四", "王五",
    "赵六", "孙七"  # 逗号后换行，自动对齐
]
```

#### 4. 命名规则：见名知意

变量、函数、类的名字要能反映其用途，避免用 `a` `b` `x` 等无意义的名字。

| 类型 | 规则 | 示例 |
|:-----|:-----|:-----|
| **变量 / 函数** | 小写字母 + 下划线（蛇形命名法） | `user_name = "张三"` |
| **常量** | 全大写 + 下划线 | `MAX_SCORE = 100` |
| **类名** | 每个单词首字母大写（帕斯卡命名法） | `class StudentInfo:` |

```python
# ✅ 正确：见名知意
user_name = "张三"
score_list = [90, 85, 95]

# ❌ 错误：不知道代表什么
x = "张三"
UserName = "李四"  # 不推荐：不符合 Python 习惯
```

#### 5. 空行：分隔代码块

用空行分隔不同功能的代码块，让结构更清晰（类似写文章分段）：

```python
# 第一部分：定义变量
name = "Alice"
age = 18

# 第二部分：定义函数（空行分隔）
def print_info():
    print(f"姓名：{name}，年龄：{age}")

# 第三部分：执行代码（空行分隔）
print_info()
```

### 3.1.3 工具：自动规范代码

手动遵守规范容易遗漏，推荐用工具自动格式化代码。新手只需掌握以下两种方式：

**VS Code 插件：Black Formatter**

1. VS Code 扩展中搜索 "Black Formatter" 并安装
2. 写完代码后按 `Shift+Alt+F`，自动按照 PEP 8 规范格式化（缩进、空格、换行全搞定）
3. macOS 快捷键：选中代码后按 `⌘ + K` 再按 `⌘ + F`

```python
# 格式化前
def my_example():
    a=4
    b=5*4/3
    c=a+b
    return c

# 格式化后
def my_example():
    a = 4
    b = 5 * 4 / 3
    c = a + b
    return c
```

**PyCharm 自带格式化**

写完代码后按 `Ctrl+Alt+L`（Windows / Linux）或 `Command+Option+L`（macOS），自动调整格式。

### 3.1.4 为什么要重视注释和规范？

- **对自己**：3 个月后回头看自己的代码，没有注释和规范会像看"天书"
- **对他人**：团队协作时，规范的代码能减少沟通成本（不用反复问"这行代码什么意思"）
- **对面试**：面试过程中，代码规范性是评分标准之一，杂乱的代码会减分

\begin{definitionbox}

**记住：能运行的代码只是合格，易读的代码才是优秀。**

从一开始就养成好习惯，比后期改代码轻松 10 倍。

\end{definitionbox}

### 3.1.5 小结

| 要点 | 核心规则 |
|:-----|:---------|
| **注释** | 单行用 `#`，多行用 `"""` 或 `'''`，解释"为什么"而非"是什么" |
| **缩进** | 强制用 4 个空格，区分代码块 |
| **命名** | 变量/函数用蛇形命名（`user_name`），类用帕斯卡命名（`StudentInfo`） |
| **工具** | 用 Black 或编辑器自带功能自动格式化代码 |
